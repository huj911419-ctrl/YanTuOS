# 下一步执行任务

最后更新：2026-10-17，版本 0.2.0。当前不存在阻止本机核心功能使用的已知错误；当前交付与限制见 FEATURE_STATUS / TEST_REPORT。接手时先检查代码和服务状态，不要重建项目。

## 先使用当前版本

1. `./scripts/status.sh`、`./scripts/doctor.sh` 检查本机服务；未运行时 `./scripts/start.sh`。
2. 开始记录真实任务、计时和错题；不依赖模型 API。定期 `./scripts/backup.sh`，备份另存到自己的安全介质。
3. 如要使用 iPhone，由用户按 README 选择局域网 HTTPS、信任自己的证书，再执行真机任务/计时/附件/PWA 验收。当前未开放局域网端口。
4. 如要启用模型，由用户选服务并配置密钥；仅在明确授权数据和费用后发送一次受控真实请求。记录协议兼容性和输出质量，不把 MockTransport 通过当作真实调用成功。
5. 开源前用本人 Git 身份创建本地提交，检查忽略规则，再自行决定是否创建远程仓库。当前无远程推送。

## 根据实际使用再扩展

- 先收集输入效率、复习安排、独立解题记录的实际反馈；不要按功能数量堆砌。
- 数据量增长后优先做服务端分页/范围查询与性能基准；当前面向个人规模，未做多年负载测试。
- 按选定模型实现其他原生协议；更强的符号核对、OCR、导入考纲须分别有来源、数据授权和测试。
- PWA 离线编辑、推送提醒、多用户不在当前承诺中，需单独设计同步/认证并验收。
- 依赖升级前保存完整 ZIP，修改后运行 `./scripts/test.sh`。上游 TestClient 弃用警告等待后续兼容升级，不强行更换未经测试的依赖。
